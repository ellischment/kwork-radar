# Радар заказов

Скрипт раз в 5 минут читает публичный Telegram-канал с заказами, отбирает подходящие
по тегам, бюджету и стоп-словам, просит Claude написать черновик отклика и присылает
карточку в Telegram. Хостинг: GitHub Actions, бесплатно.

## Настройка, 20 минут

### 1. Бот в Telegram (3 мин)
1. Открой @BotFather, команда `/newbot`, придумай имя. Скопируй токен.
2. Напиши своему новому боту любое сообщение (иначе он не сможет писать тебе первым).
3. Узнай свой chat_id: открой в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   и найди `"chat":{"id":123456789`. Это число и есть TG_CHAT_ID.

### 2. Ключ API не нужен
В `config.yaml` стоит `draft_enabled: false`. Бот присылает только отфильтрованные заказы
со ссылкой. Отклик ты просишь у Claude в чате: пересылаешь карточку, получаешь текст.
Секрет `LLM_API_KEY` создавать не нужно. Позже можно поставить `draft_enabled: true`
и подключить любого провайдера (см. комментарии в `config.yaml`).

### 3. Репозиторий на GitHub (5 мин)
1. Создай **публичный** репозиторий, например `kwork-radar` (почему публичный, см. «Ограничения»).
2. Загрузи туда все файлы из этой папки (можно через веб-интерфейс, Add file → Upload files).
   Папка `.github/workflows/` должна сохранить структуру.
3. Settings → Secrets and variables → Actions → New repository secret. Добавь два:
   - `TG_BOT_TOKEN`
   - `TG_CHAT_ID`
4. Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save.
   Без этого скрипт не сможет сохранять `state.json`.

### 4. Конфиг (5 мин)
Открой `config.yaml`:
- `channel`: имя канала без @. Канал должен быть публичным, иначе t.me/s/ его не отдаст.
- `min_budget`, `tags_allow`, `stop_words`: подправь под себя.
- `profile`: проверь, что там правда про тебя, и ссылку на портфолио.

### 5. Первый запуск
Actions → kwork-radar → Run workflow. Первый прогон только запоминает историю канала
и ничего не присылает. Со второго прогона (через 5 минут) пойдут карточки.

## Как пользоваться
Пришла карточка → читаешь ОЦЕНКУ (две секунды) → если «Брать», копируешь ОТКЛИК,
правишь одну-две фразы под себя и вставляешь на Kwork. Задержка от публикации
до твоего отклика получается 3–10 минут, это первая волна.

Отправка на Kwork остаётся ручной намеренно: автоотклики там банят, а последняя
строка отклика (точный вопрос) стоит того, чтобы проверить её глазами.

## Ограничения
- GitHub иногда задерживает крон на 5–15 минут, особенно в начале часа.
- Если канал закрытый или t.me/s/ отдаёт пустую страницу, скрипт напишет
  «Получено постов: 0». Тогда нужен вариант с Telethon на домашней машине.
- Минуты Actions. GitHub округляет каждый прогон до целой минуты, поэтому
  288 прогонов в день это около 8 600 минут в месяц. Лимит приватного репозитория 2 000.
  Поэтому репозиторий лучше сделать **публичным**: для публичных минуты не считаются.
  Секреты при этом остаются скрытыми, виден только код и `config.yaml`
  (там твой профиль для отклика, ничего личного в него не пиши).
  Если хочешь именно приватный, крон придётся поставить `*/30`, а это уже поздно для первой волны.

## Локальный запуск для проверки
```bash
pip install -r requirements.txt
export TG_BOT_TOKEN=... TG_CHAT_ID=... LLM_API_KEY=...
python radar.py
```
